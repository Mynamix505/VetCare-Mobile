# Flutter-клиент VetCare Mobile

Первый реализованный сценарий: список питомцев → карточка питомца → возврат. Предусмотрены загрузка, пустой список, ошибка, повторная попытка и обновление жестом. Экран ограничивает ширину на планшетах, допускает прокрутку и сохраняет системный масштаб текста. Provider управляет состоянием; Dio находится в слое данных. ScreenUtil используется для адаптивных отступов.

## Подготовка и запуск

Flutter SDK в окружении разработки агента не найден. Исходники созданы вручную; платформенные Android/iOS-проекты ещё не сгенерированы, зависимости не установлены, сборка и Dart-анализ не выполнялись.

После установки Flutter со встроенным Dart 3.6+ выполните из корня репозитория:

```powershell
flutter --version
flutter create --platforms=android,ios --project-name vetcare_mobile --org ua.vettech --no-pub .
flutter pub get
dart format lib test/mobile
flutter analyze
flutter test test/mobile
flutter run --dart-define=DEMO_MODE=true
```

`ua.vettech` — предварительный идентификатор организации, его нужно определить до публикации в магазинах. Команда `flutter create` создаёт недостающие платформенные файлы; не применяйте `--overwrite` к существующим исходникам. Если Flutter создаст стандартный `test/widget_test.dart` со счётчиком, удалите этот шаблонный тест: приложение тестируется в `test/mobile/`. Для iOS-сборки нужны macOS и Xcode. После `pub get` сохраните `pubspec.lock` в Git.

Деморежим включён по умолчанию и явно отмечен в интерфейсе. Он показывает вымышленных питомцев и не обращается к серверу. Медицинские записи не имитируются; карточка сообщает, что история пока недоступна.

## Подключение API

Текущий backend реализует только health endpoints. Следующий контракт предложен для разработки клиента и **ещё не реализован сервером**:

```http
GET /api/v1/pets
```

```json
{
  "data": [
    {"id": "pet-1", "name": "Луна", "species": "Собака", "breed": "Корги"}
  ]
}
```

`id`, `name`, `species` — непустые строки; `breed` — строка или null. Ошибочный формат вызывает сообщение об ошибке, а не подменяется демоданными. Пагинация, авторизация и медицинская история будут добавлены вместе с согласованным API.

После реализации API и настройки доступа устройства к HTTPS-серверу:

```powershell
flutter run --dart-define=DEMO_MODE=false --dart-define=API_BASE_URL=https://your-api.example
```

Замените пример реальным адресом. `API_BASE_URL` — origin без пути `/api/v1`; пути задаются в `ApiEndpoints`. Не передавайте токены через `dart-define`. Для локального HTTP нужны отдельные настройки платформы; localhost на телефоне не указывает на компьютер разработчика. До выпуска Android-приложения проверьте разрешение INTERNET в основном manifest. JWT, безопасное хранение и обработка сессии пока не реализованы.

## Проверки

Добавлены тесты валидации DTO, параллельных запросов, повторной попытки, пустого результата, завершения запроса после dispose и перехода в карточку. Пока они **не запускались**, поскольку Flutter SDK отсутствует. Ручные проверки после запуска: экран 320 px, планшет, увеличенный системный шрифт, ошибка сети и восстановление.

Основа реализации: [Flutter — Provider и ChangeNotifier](https://docs.flutter.dev/data-and-backend/state-mgmt/simple), [Dio](https://pub.dev/packages/dio), [ScreenUtil](https://pub.dev/packages/flutter_screenutil).

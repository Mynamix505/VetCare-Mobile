# План розробки VetCare Mobile

Основа: `codex.md`. Документ визначає стек і шари архітектури, але не містить повної специфікації API. Обрано JavaScript ESM, Express, Sequelize, PostgreSQL, Redis та Zod із запропонованих альтернатив.

## 1. Основа проєкту
- [x] Створити структуру `src`, відокремити Express app від запуску сервера.
- [x] Додати конфігурацію середовища, перевірку через Zod та `.env.example`.
- [x] Налаштувати клієнти PostgreSQL і Redis, завершення роботи та обробку помилок запуску.
- [x] Додати CORS, захисні заголовки, JSON-помилки та журналювання без тіл запитів і секретів.
- [x] Реалізувати liveness/readiness через routes → controllers → services → models.
- [x] Підготувати Docker Compose для локальних залежностей та README.
- [x] Перевірити синтаксис усіх JavaScript-файлів.
- [x] Виконати 3 тести healthService: успіх, відмови, таймаут.
- [ ] Виконати HTTP-тести після встановлення пакетів: npm registry недоступний (`EACCES`), локальний кеш порожній; `npm test` наразі зупиняється на відсутньому Express.
- [ ] Перевірити запуск із реальними PostgreSQL та Redis (Docker наразі недоступний).

## 2. Дані та авторизація
- [ ] Узгодити мінімальні поля користувача, ролі та права доступу.
- [ ] Додати міграції User, Pet, Veterinarian, Appointment та обмеження цілісності.
- [ ] Реалізувати реєстрацію, хешування паролів, вхід і JWT middleware.
- [ ] Визначити строк життя токенів, refresh/logout та обмеження частоти входу.
- [ ] Перевірити відмову доступу без токена та із простроченим токеном.

## 3. Питомці
- [ ] Реалізувати CRUD `/api/v1/pets`, валідацію та пагінацію.
- [ ] Обмежити операції власником; перевірити спроби доступу до чужих записів.

## 4. Запис до лікаря
- [ ] Визначити робочі години, часовий пояс клініки, тривалість прийому та правила скасування.
- [ ] Реалізувати перегляд слотів і `/api/v1/appointments`.
- [ ] Захистити від одночасного бронювання через транзакції та обмеження БД.
- [ ] Перевірити конкурентне бронювання і граничні значення часу.

## 5. Вакцинації та завершення API
- [ ] Визначити дані вакцинацій і правила нагадувань; не вигадувати медичні інтервали.
- [ ] Реалізувати історію та нагадування згідно з визначеними правилами.
- [ ] Додати OpenAPI, інтеграційні тести з БД та CI.

Перший етап не включає реалізовану авторизацію або бізнес-моделі: це наступні пункти плану.

Найближчий крок: у середовищі з доступом до npm виконати `npm.cmd install`, зберегти створений `package-lock.json`, запустити `npm.cmd test`, потім PostgreSQL/Redis та перевірки HTTP за README. Після цього переходити до етапу 2.
